# Ядро обнаружения препятствий по лидару (v0.1-mvp)

Ядро получает один кадр облака точек переднего лидара поезда метро. Оно находит пол, ось пути и нормативный габарит приближения строений (контур Ом, ГОСТ 23961-2024). Всё, что попало внутрь габарита выше пола, собирается в кластеры и подтверждается во времени («3 кадра из 5»). На выходе — есть ли препятствие и расстояние до ближайшего. Других датчиков ядру не нужно: ни одометрии, ни TF, ни камер. Машинного обучения нет, только геометрия. Ядро — чистая библиотека на numpy без ROS; нода вызывает её на каждый кадр.

## Установка

Python 3.12.

```bash
pip install -r requirements-core.txt    # только ядро: numpy, PyYAML, scipy
pip install -r requirements-tools.txt   # + чтение записей, тесты, визуализация
```

Для ноды достаточно `requirements-core.txt`. В ядре нет импортов ROS, sklearn, open3d, rosbags и matplotlib — это проверяется тестом.

Потоки BLAS задавайте явно — от них зависит время кадра:

```bash
export OMP_NUM_THREADS=8 OPENBLAS_NUM_THREADS=8
```

## API

```python
from core.config import Config
from core.pipeline import ObstacleDetector

detector = ObstacleDetector(Config.from_yaml("configs/default.yaml"))
result = detector.process(xyz, intensity, ring, t_rel, stamp_ns, frame_gap=1)
```

Все параметры лежат в `configs/default.yaml`. Если ключа не хватает или есть лишний, загрузка завершается ошибкой.

**Вход `process()`** — сырой кадр `PointCloud2` без каких-либо преобразований, со всеми точками, включая пустые лучи (0, 0, 0):

| аргумент | что | форма, тип |
|---|---|---|
| `xyz` | поля `x`, `y`, `z` | (N, 3), float32 |
| `intensity` | поле `intensity` | (N,), float32 |
| `ring` | поле `ring` | (N,), uint16 |
| `t_rel` | поле `timestamp` точек (часы сенсора; используются только разности) | (N,), float64 |
| `stamp_ns` | `header.stamp` в наносекундах | int |
| `frame_gap` | сколько кадров записи прошло с прошлого вызова (1 — ни одного не пропущено) | int |

Раскладка точки упакованная, без выравнивания: `timestamp` лежит по смещению 18. Поэтому dtype строится по `fields` сообщения с явными `offsets` и `itemsize = point_step`. Готовая функция — `cloud_to_arrays()` в `examples/run_frames.py`; `msg.data` из rclpy подходит для `np.frombuffer` так же.

**`reset()`** вызывайте при старте ноды и при скачке записи (перемотка, новая запись). Пропуски кадров сообщаются через `frame_gap`, а не через `reset()`; между соседними кадрами он не нужен. После него снова идёт холодный старт (см. ограничения).

Кадры подаются строго по одному и по порядку. Если нода пропускает кадры, передайте их число в `frame_gap`.

## Выход

`FrameResult` (контракт заморожен):

| поле | смысл |
|---|---|
| `obstacle_found` | есть подтверждённое препятствие в габарите |
| `nearest_distance_m` | дистанция до ближайшего подтверждённого препятствия или `None` |
| `detections` | список `Detection` — только подтверждённые |
| `debug` | диагностика, см. ниже |

`Detection`:

| поле | смысл |
|---|---|
| `distance_m` | продольная координата x ближайшей точки кластера |
| `centroid_xyz`, `bbox_min_xyz`, `bbox_max_xyz` | центр и рамка кластера |
| `n_points` | точек в кластере |
| `score` | уверенность 0…1: запас до кромки габарита против неопределённости оси |
| `source` | `gauge` |

**Система координат выхода — система пути, не лидара:** X вдоль пути вперёд, Y влево, Z вверх; z = 0 на плоскости путевого основания; начало — проекция сенсора на эту плоскость. **`distance_m` — вдоль пути** (продольная x), не дальность по лучу и не от лобовой части состава.

### Что из `debug` нужно ноде

| ключ | смысл |
|---|---|
| `checked` | **читать первым.** `False` — кадр непригоден (пустой, без возвратов); тогда нет ключей `axis`, `corridor`, `frame_transform`. `obstacle_found = False` без `checked = True` — это «не проверено», а не «путь свободен» |
| `frame_gap` | сколько кадров прошло с прошлого проверенного, с учётом непригодных |
| `axis.state` | `measured` / `held` (ось удерживается по прошлым кадрам) / `degraded` / `lost`. **При потере оси это словарь со `state == "lost"`, не `None`** |
| `axis.reason` | почему ось не измерена: `anchor_uninitialised` (холодный старт), `tracer_failed` (рельсы не найдены), `gate_rejected`, `outlier_rejected`; у измеренной — `None` |
| `corridor.x_m` | `[ближняя, дальняя]` граница проверенного участка, м. Дальше дальней границы «пусто» не значит «свободно» |
| `frame_transform` | преобразование лидар → путь: `p_track = R @ p_lidar + t`, ключи `rotation` (3×3) и `translation_m` |
| `verdict` | правило остановки при потере оси: `stop` (bool), `reason` |

**TF.** Плоскость пола оценивается заново в каждом кадре, поэтому преобразование динамическое. Публикуйте на каждый проверенный кадр TF от `frame_id` облака к системе пути (например, `track`) со штампом кадра: трансляция `t`, кватернион из `R`. Рамки и ось рисуйте в `track`. С `frame_id` облака они окажутся повёрнутыми на 90° и поднятыми на высоту сенсора.

**Остановка.** Тормозить стоит при `obstacle_found` или `verdict.stop`. Второе срабатывает, когда ось пропала, а незадолго до этого в коридоре был кластер.

## Пример без ROS

```bash
python examples/run_frames.py doubleT_platform --frames 5
python examples/run_frames.py doubleT_platform --frames 0 --jsonl out/example/doubleT_platform.jsonl
```

Скрипт читает кадры из записи rosbag2 (пакет `rosbags`, без ROS), раскладывает `PointCloud2` в массивы, подаёт в ядро `header.stamp` и печатает `FrameResult`. Флаг `--jsonl` пишет выход покадрово в формате `tools.compare_runs`.

## Известные ограничения

Числа взяты из прогонов текущего кода. Где не указано иное, при `OMP_NUM_THREADS=8`.

**Ложные тревоги на пяти записях без препятствий** (2287 кадров, 3.8 мин):

| запись | кадров с кандидатом | с тревогой | эпизодов |
|---|---:|---:|---:|
| `doubleT_platform` | 16 | 4 | 1 |
| `roundT_doubleT` | 0 | 0 | 0 |
| `roundT_pressureGate_roundT` | 4 | 0 | 0 |
| `roundT_squareT_pressureGate_squareT` | 10 | 5 | 1 |
| `squareT_platform_squareT_switch` | 50 | 18 | 3 |
| **всего** | **80** | **27** | **5 — 1.3 в минуту** |

Кандидат — кластер до подтверждения. Эпизод — одна команда на торможение: тревоги с паузой не больше 1 с.

```bash
python -m tools.run_layer_a --config configs/default.yaml --records <запись> --out runs/confirm_fix
python -m tools.false_alarm_table --config configs/default.yaml --runs runs/confirm_fix --summary
python -m tools.confirm_sweep --config configs/default.yaml --runs runs/confirm_fix --advance-from debug --required 3 --window 5
```

**Известные семейства ложных.** Это конструкции, стоящие в 0–30 мм снаружи кромки Ом: тревогу решают сантиметры ошибки оси и шума.
- Конструкция у правой кромки за концом рельсовой базы на `roundT_squareT`: лицо в +16…+30 мм от кромки, эпизод на кадрах 32–37.
- Грань в верхнем боковом углу габарита на стрелочной записи: −2…+25 мм, кадры 232–296 и 723–728.

Исправление в работе (`tools/measure_corner.py`, `tools/measure_wall.py`).

**Холодный старт.** После запуска и после `reset()` коридора нет, пока ось не захвачена: 0 / 9 / 11 / 0 / 0 / 34 кадра по шести записям (до 3.4 с). Тело в сцене задерживает захват: фигура на оси — на 3 кадра, брусок у кромки — на 16 (`tools/scenarios.py --trace-anchor`).

```bash
python -m tools.axis_coverage --runs runs/confirm_fix
```

**Рабочая зона.**
- От 5 м до конца рельсовой базы: медиана 21.3–26.3 м по записям. Ближе 5 м — слепая зона.
- В 8.0 % кадров (198 из 2488) база продлена по полосе основания: коридор до 31 м по медиане, p90 41 м, максимум 51 м. На продлённом участке ось смещена вправо на 62–115 мм (`tools/measure_extension_residual.py`).

**Ближняя зона 5–10 м хуже средней.** Предмет 0.24 × 0.25 м (0.042 м² над полом габарита) находится в 20 кадрах из 71 (28 %) на 5–10 м против 161 из 170 (95 %) на 10–24 м. Причина — лучи по углу места неравномерны (DATA.md §3.7).

```bash
python -m tools.scenarios --config configs/default.yaml --scenario approach --record roundT_doubleT \
    --advance-m 1.7 --distance-m 22 --first-frame 10 --last-frame 251 --via-pipeline --no-confirm \
    --body-radius 0.12 --body-height 0.25 --out out/mvp_near
```

**Время кадра, 8 потоков BLAS, вне кадров полного RANSAC:**

| облако | запись | медиана | p90 | p99 | полный RANSAC (раз в 51 кадр ≈ 5.1 с) |
|---|---|---:|---:|---:|---:|
| 921 600 точек | `doubleT_obstacle` | 76.8 мс | 84.0 мс | 88.5 мс | 204–283 мс, первый кадр 359 мс |
| 307 200 точек | `doubleT_platform` | 43.9 мс | 49.4 мс | 57.5 мс | 96–148 мс, первый кадр 231 мс |

- Замер на 921k сделан только на стоящем составе: другой записи 921k нет.
- Прежние замеры на 307k (медиана 45.5–47.5 мс, p90 51.6–54.4 мс) сняты без записи числа потоков.

```bash
python -m tools.run_layer_a --config configs/default.yaml --records doubleT_obstacle --out runs/mvp_obstacle
python -m tools.timing_table --config configs/default.yaml --runs runs/mvp_obstacle
```

**Установка 921k (`doubleT_obstacle`, лидар на 1.71 м).** Ось удерживается, а не измеряется, в 53 кадрах из 201 (26 %), везде `tracer_failed`. Состав там стоит, поэтому коридор не теряется. На ходу серия из 3 кадров — это около 5 м из 8.24 м допустимого удержания. Причина не разобрана.

## Проверка ноды

Ядро детерминировано. Одна и та же запись через ноду должна дать ровно те же числа. Если нода даёт другие, ошибка в обвязке, а не в ядре. Выход не зависит от того, какой штамп подаётся: `header.stamp` или время записи rosbag2. Проверено: 0 расхождений на 345 кадрах.

**1. Позитив — копия `roundT_doubleT` со вписанной фигурой 0.5 × 1.7 м** (`roundT_doubleT_approach_figure` и `figure_truth.json`, передаются отдельно). Вся запись, 252 кадра:

| что считать | ожидается |
|---|---:|
| кадров с `candidates_raw` не пустым | 226 |
| из них с кандидатом на фигуре | 224 |
| кадров с `obstacle_found` | **174** |
| из них тревога на фигуре | **174** (мимо — 0) |
| кадров с `axis.state == "lost"` | 14 |

```bash
python -m tools.figure_match --config configs/default.yaml \
    --bag <путь>/roundT_doubleT_approach_figure --first 0 --last 251
```

**2. Чистая запись `doubleT_platform`, 345 кадров:**

| что считать | ожидается |
|---|---|
| кадров с кандидатом | 16: 21, 23–29, 35, 59, 100, 102, 150, 155, 263, 264 |
| кадров с `obstacle_found` | 4: 24, 27, 28, 29 |
| эпизодов | 1 (кадры 24–29, первая тревога на 18.7 м) |

```bash
python examples/run_frames.py <путь>/doubleT_platform --frames 0 --jsonl out/check/doubleT_platform.jsonl
```

Сверить `obstacle_found` по кадрам с таблицей: тревоги ровно в кадрах 24, 27, 28, 29.

Номер кадра — порядковый номер сообщения в записи, с нуля.
